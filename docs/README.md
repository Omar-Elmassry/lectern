## What this project is

Lectern is a VS Code extension that opens Markdown files in a **distraction-free
reading view** (a custom text editor), not an Obsidian clone. It renders GFM, callouts,
clickable task lists, wiki links, front matter, code with syntax highlighting, KaTeX math,
Mermaid diagrams (with a full-screen viewer) and emoji shortcodes, plus an outline and a
small in-view settings panel: five reading palettes (editor/light/sepia/dark/black),
font, text size, line width and line spacing.

- Extension id `OmarElmasry.lectern`; commands and settings use the `lectern.` prefix.
- Custom editor `viewType = lectern.reader`, registered for `*.md`, `*.markdown`, `*.mdx`
  with `priority: "option"` (opt-in, never the default editor on its own).
- Called `reader-md` before its first release (1.0.0); see `history.md`.
- Requires VS Code `^1.82.0` (Chromium 111+ for `color-mix()`; see `theming.md`).

## Current state (1.0.0)

First public release. `npm test` runs 62 `node:test` cases over the renderer (tasks,
callouts, headings, assets, wiki links, front matter, math, emoji, word count), the wiki
resolver and the settings schema; `webtest` and `hosttest` cover the webview and the
provider end to end. Visual and interaction checks (theming, the diagram viewer, CSP) are
done in Chromium through `scripts/preview.mjs`, which applies the real webview's CSP.
`CHANGELOG.md` lists what 1.0.0 contains; `history.md` explains how it got there.

## Ground rules for future work

1. **Never edit `package.json` by hand.** It is generated by `scripts/make-package.mjs`.
   Edit the template there and re-run it.
2. **Keep `marked` at `^13`.** It is pinned deliberately (renderer API). See `development.md`.
3. **Do not add `backdrop-filter` or translucent (`... / <alpha>`, `color-mix(..., transparent)`)
   backgrounds.** They caused GPU compositing artifacts in the webview. Use opaque
   `color-mix(..., var(--rd-bg))` instead. See `theming.md`.
4. **Verify in the right DevTools.** Webview console only; a Lectern tab must be active.
   See `debugging.md` §1 before trusting any console output.
5. Run the full check loop before packaging: `npm run typecheck`, `npm test`,
   `npm run compile`, `webtest`, `hosttest` (CI runs the same on Ubuntu and Windows).
   See `development.md`.
6. **Never render task checkboxes `disabled`** if they should be clickable: Chromium drops
   clicks on disabled controls (happy-dom does not, so only a browser check catches it).
7. **Keep Mermaid on demand.** It's ~5 MB; only `drawDiagrams()` may load
   `dist/webview/mermaid.js`, and only when a note has a diagram.
